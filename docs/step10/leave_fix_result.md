# 10단계 이탈(멀어질 때) 알람 고치기: 지원님 기록으로 다시 확인 (2026-11-02)

지원님 앱 사본(~/eg2-lab/prox_leave_fix/, 원본·지원님 폴더는 그대로)에 두 가지를 넣었다.
- A) --leave-single: 한 카메라(single) 위치도 이탈 판단에만 쓴다. 근접 알람은 지금처럼 stereo만.
- B) --far 기본값 3.0 → 2.0
- 고친 앱: proximity_app_leave.py (원본 proximity_app_cpu.py와 차이 7줄, patch_app.py). 실제 카메라로는 돌리지 않았다(웹캠은 지원님 서비스가 사용 중).
- 실행 예: python proximity_app_leave.py --cams 2 0 --target "red mickey mouse trash can" --near 1.0 --leave-single --port <자기 포트>

## 방법
지원님 기록(state_logger, 0.3초마다 사람별 위치·타겟 거리 d·stereo/single)을 트랙별로 앱과 같은 ProximityAlarm에 다시 넣었다 (replay.py).
- runs/fused_log.csv (10-28 14:48–15:14): 10-6 시나리오 1차 15:04:51–15:06:35, 2차 15:10:33–15:12:43 포함
- runs/fused_moving_log.csv (10-29 09:51–10:07): 10-8 이동 타겟 (충돌 5·지나가기 5 회차 포함)
- 한계: 기록은 0.3초 간격 상태라 앱 안의 프레임별 갱신과 조금 다를 수 있다. 기록 d는 single이면 키 1.2m 가정 위치로 잰 값(오차 55–90cm).

## 결과 1: 10-6 시나리오 (10-28 기록)
기록 전체에서 d 최대값이 stereo 1.83m, single 2.21m → 3m 밖은 한 번도 기록되지 않음. 그래서 3m 기준으로는 어떤 방법도 이탈 알람이 날 수 없다.

| 방법 | 이탈 시나리오(2차, #29) | 다른 구간 이탈 알람 | 근접 알람 변화 |
| --- | --- | --- | --- |
| 원래 (stereo만, 3m) | 0 | 0 | - |
| A (single 포함, 3m) | 0 | 0 | 없음 |
| B (stereo만, 2m) | 0 (#29 stereo 최대 d가 2m 미만) | 0 | 없음 |
| **A+B (single 포함, 2m)** | **1** (15:11:06, #29 single d 2.09m) | 1 (15:12:45, #36 앉았던 사람이 일어나 멀어짐 d 2.02m) | 2차에 근접 1회 늘어남 (#29가 이탈 후 다시 다가온 것) |

- 15:11:33 이후 #29가 화면 밖으로 퇴장한 것은 마지막 위치가 d 약 1m라 어느 방법으로도 이탈이 안 남 (cam0 쪽 화면 밖으로 바로 나감).
- 다가가기·서 있기·지나가기·앉기 구간에서 새로 생긴 잘못된 알람은 없다.

## 결론
- 지금 교실 배치에서는 A+B(이탈 판단에 single 포함 + far 2m)를 같이 써야 이탈 알람이 난다. 지원님 이탈 시도에서 1번 울림.
- A만으로는 안 된다(3m까지 가는 기록이 없음). B만으로도 안 된다(2m 밖은 대부분 single로만 보임).
- 대가: 2m 밖으로 나가는 모든 움직임에 울려 알람이 늘어난다(10-8 기록 2 → 8). 중복 억제를 이탈에도 넣는 것을 권장.
- 확실히 확인하려면 실제 카메라로 "0.5m → 2.5m 이상 멀어지기"를 3번 해 봐야 한다. 지원님 서비스가 웹캠을 쓰지 않을 때.
